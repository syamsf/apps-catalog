# apps-catalog

Internal developer portal. Lists every internal app with its URLs, owner, contact and links,
shows if each app is up, and uses Authelia (OIDC) for login. Admins add and edit apps, groups
and settings in the portal itself.
See [docs/design.md](docs/design.md) for the design.

- Backend: Go with Fiber v3 (`cmd/portal`, `internal/`), config with viper, logs with zerolog
- API docs: Swagger UI at `/api/docs/index.html`, generated by swag from the handler comments
- Frontend: Vue 3 + Vite + Tailwind (`web/`), embedded into the Go binary
- Database: PostgreSQL through pgx, migrations (goose) run on startup
- Image: one Docker image, built by GitHub Actions and pushed to `ghcr.io/<owner>/<repo>`

## Run locally

```sh
make db          # postgres in docker on :5432
make web         # build the frontend once
make run         # api + ui on http://localhost:8080
make import      # optional: add the sample apps in ./catalog once
make web-dev     # optional: vite dev server on :5173 with hot reload
```

### Hot reload and debugging

```sh
make dev         # air: rebuilds and restarts on .go, .sql and .yaml changes, debug logs
make debug       # same, but runs under delve on localhost:2345
```

air and delve are pinned in `tools/go.mod` and run with `go tool`, nothing to install.
Each rebuild also regenerates the swagger docs.

To debug, run `make debug` and attach your editor to `localhost:2345`
(VS Code: a `"request": "attach", "mode": "remote"` launch config, GoLand: Go Remote).
From a terminal: `go tool -modfile=tools/go.mod dlv connect 127.0.0.1:2345`.

Or everything in docker:

```sh
docker compose up --build
```

## Commands

```
portal serve [-config file]          start the api and web ui
portal import [-config file] [-update] [file|dir]
                                     add apps from an import file or a yaml catalog dir,
                                     skips existing ids, -update replaces them (files only)
portal user add [-admin] [-name n] [-email e] <username>
                                     add a local user, asks for the password
portal user passwd <username>        set a new password for a local user
portal validate <dir>                check the yaml catalog, exit 1 on errors
portal version
```

## Config

Settings come from an optional yaml file (`-config file` or `CONFIG_FILE`) and from env vars.
Env vars win. See [config.example.yaml](config.example.yaml).

| `database.url` | `DATABASE_URL` | | required |
| `http.addr` | `HTTP_ADDR` | `:8080` | |
| `http.public_url` | `HTTP_PUBLIC_URL` | | e.g. `https://portal.internal.yourcompany.id`, needed for login |
| `catalog.dir` | `CATALOG_DIR` | | default dir for `portal import` |
| `health.interval` | `HEALTH_INTERVAL` | `60s` | `0` turns health checks off |

| `oidc.client_id` | `OIDC_CLIENT_ID` | | |
| `oidc.client_secret` | `OIDC_CLIENT_SECRET` | | |

## Apps, groups and admins

Apps live in the database and are managed in the admin area at `/admin`: dashboard, apps, groups,
users and settings. Every change there is written to the change log on the dashboard.

- Admin rights of SSO users come from the sso group in `AUTH_ADMIN_GROUP`, read at each sign-in. Change it in LLDAP.
  Portal accounts (local login) get the admin role on the Users page or with `portal user add -admin`.
- Groups are managed in the portal, not in LLDAP. A group is a set of people and a set of apps.
- An app is shared with everyone who signs in, or only with members of some groups. Admins see every app.
- People show up on the Users page after their first sign-in. Someone in no group only sees apps shared with everyone.
- Opening an app you can't see shows which groups have it and the admin contact email from Settings.
- An app's owner is a group. Its members edit the app's details at `/apps/:id/edit`, and the team has a page at `/teams/:name`.
- Searches and app opens are logged (90 and 180 days). The dashboard shows usage for the last 7 days, searches with
  no results and access requests. People without access can request it from the app page; admins approve by picking one of the app's groups.
- Settings has the portal name, admin email, the category, runs on and environment lists (one URL field per
  environment on the app form), the default icon colors and what new apps are shared with by default.
- Apps can have an uploaded icon (PNG at least 128 x 128 or SVG, up to 256 KB), a [Tabler](https://tabler.io/icons)
  icon on a color, or their initials on a color. Choose icon on the app form searches Tabler (bundled, works
  offline) and [Dashboard Icons](https://dashboardicons.com) (loaded from jsDelivr by the admin's browser; the
  logo picked is saved in the portal like an upload). `make tabler-icons` refreshes the bundled Tabler set.

### Importing apps from a file

One yaml file with a list of apps, uploaded on Admin > Apps > Import or passed to `portal import file.yaml`.
The page shows what is new, what already exists and every problem with its line number before anything is
saved. The format is in [docs/import.md](docs/import.md), with a full example in
[web/public/import-example.yaml](web/public/import-example.yaml).

### Importing a yaml catalog dir

The older format: `portal import <dir>` adds apps from yaml files, one file per app, and skips ids that already exist, so it is safe
to run again. Groups, categories and environments that don't exist yet are created. After the import the
apps are edited in the portal; the files are not read again.

```yaml
id: grafana            # lowercase, numbers and dashes, never reused
name: Grafana
description: Dashboards for all services
owner: platform
contact: platform-team@yourcompany.id
category: monitoring
urls:
  prod: https://grafana.internal.yourcompany.id
links:
  repo: https://gitea.yourcompany.id/platform/grafana-config
access: Ask in the platform team channel
health_url: /healthz   # optional
allowed_groups:        # optional, only these portal groups see the app
  - platform
```

Unknown fields are rejected. If any file is invalid nothing is imported. `portal validate <dir>` checks the files.

## Health checks

Every `HEALTH_INTERVAL` the portal sends a GET to each app. The target is `health_url`
if it is a full URL, `health_url` joined to the prod URL if it is a path, or else the prod URL.

- Up: any response below 500 within `HEALTH_TIMEOUT`. Redirects are not followed, so a 302 to a login page is up.
- Down: timeout, connection error or a 5xx.

The portal needs network access to every app it checks.

## Sign-in

There are two ways to sign in, and both can be on at the same time:

- **Company SSO** (Authelia, OIDC), on when `OIDC_ISSUER` is set. See below.
- **Portal accounts**, on when `AUTH_LOCAL_LOGIN=true`. A username and password stored in the portal
  (bcrypt). Admins add them on the Users page, where they can also set a new password, change the admin
  role or remove the account. People change their own password from the Password link in the header.
  After 5 wrong passwords for a username from one IP, sign-in is blocked for 15 minutes.

With local login only, add the first admin from the command line, then sign in at `/admin/login`:

```sh
portal user add -admin -name "Alex" alex       # asks for the password twice
docker compose exec portal /portal user add -admin alex
```

Without `OIDC_ISSUER` and without local login there is no sign-in at all and every request is a local
admin, which is only meant for local development.

Behind https, set `HTTP_PUBLIC_URL` to the https address so the session cookie is marked secure.

### Login with Authelia

Register the portal as a client in Authelia:

```yaml
identity_providers:
  oidc:
    clients:
      - client_id: 'app-catalog'
        client_name: 'App Catalog'
        client_secret: '$pbkdf2-sha512$...'  # authelia crypto hash generate pbkdf2
        public: false
        authorization_policy: 'one_factor'
        require_pkce: true
        pkce_challenge_method: 'S256'
        redirect_uris:
          - 'https://portal.internal.yourcompany.id/auth/callback'
        scopes: ['openid', 'profile', 'email', 'groups']
        response_types: ['code']
        grant_types: ['authorization_code']
        token_endpoint_auth_method: 'client_secret_basic'
```

Then set `OIDC_ISSUER`, `OIDC_CLIENT_ID=app-catalog`, `OIDC_CLIENT_SECRET` (the plain secret) and `HTTP_PUBLIC_URL`.
Groups are read from the userinfo endpoint, so no claims policy is needed in Authelia.

Everyone in `AUTH_ADMIN_GROUP` is a portal admin. Other people see the apps shared with everyone and with their portal groups.
`AUTH_LOGOUT_URL` is only used for SSO users; portal accounts go back to the sign-in page.

## API

The full reference is the Swagger UI at `/api/docs/index.html` (needs login when login is on).
After changing a handler or its comments run `make docs`; CI fails when the generated docs are out of date.


| Method | Path | |
| --- | --- | --- |
| GET | `/api/portal` | portal name, no login needed |
| GET | `/api/me` | current user, `login_enabled` |
| GET | `/api/settings` | options, icon colors, read only |
| GET | `/api/apps?q=&category=&runs_on=&group=` | list and search |
| GET | `/api/apps/{id}` | one app, 403 with the groups that have it when it's not shared with you |
| GET | `/api/apps/{id}/icon` | uploaded icon |
| PUT, DELETE | `/api/apps/{id}/icon` | upload or remove the icon, admins and the owner team |
| PUT | `/api/apps/{id}/details` | edit an app's details, admins and the owner team |
| POST | `/api/apps/{id}/open` | record that you opened an app |
| POST | `/api/apps/{id}/access-requests` | ask for access to an app you can't see |
| POST | `/api/searches` | record a search |
| GET | `/api/teams/{name}` | a team's members and the apps it owns |
| GET | `/api/icons/tabler` | every Tabler icon, for the picker |
| GET | `/api/icons/tabler/{name}.svg` | one Tabler icon |
| GET | `/api/facets` | categories and runs on options with counts |
| PUT, DELETE | `/api/favorites/{id}` | star and unstar |
| PUT | `/api/me/password` | change my password, portal accounts only |
| | `/api/admin/...` | dashboard, apps, groups, users and portal accounts, settings, options, access requests, failed searches (admins only) |
| GET | `/healthz` | db check, no login needed |
| GET | `/auth/login?redirect=/path` | start login |
| GET | `/auth/callback` | OIDC redirect uri |
| POST | `/auth/local` | sign in with `{"username", "password"}`, when local login is on |
| POST | `/auth/logout` | sign out |

Everything under `/api` except `/api/portal` needs a session when login is on, otherwise it returns 401.
`/api/admin` returns 403 for people who are not admins.

## Tests

```sh
make db && make test
```

Store tests need `TEST_DATABASE_URL` and empty every table, so point it at a throwaway database.
`make db` creates `portal_test` for this and `make test` uses it.
